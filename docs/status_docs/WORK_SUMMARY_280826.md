# Work Summary — 28 August 2026

## What was built

New prototype track comparing cheaper OpenRouter models against production Haiku on the taxon-resolution call site (`services/anthropic_client.py::resolve_taxon_filters`), scoped there deliberately since it's the harder bar to clear (forced tool-use, exact-match ground truth) versus narration's judged free text.

- **`prototypes/scripts/model_comparison_spike.py`** (new) — copies (not imports) `TAXON_GUIDANCE`/`QUERY_SCHEMA_TOOL` from `services/anthropic_client.py` and the 25 seeded queries + expected filters from `app/backend/tests/evals/test_taxon_resolution_eval.py`. No GBIF calls at all — pure LLM output comparison. Candidates call OpenRouter's OpenAI-compatible chat completions endpoint via plain `httpx` (matches `services/tts.py`'s existing pattern, no OpenAI SDK). Runs sequentially, at each provider's default temperature (unset, matching prod's real Haiku behaviour). Requests OpenRouter's real per-call cost via `usage: {include: true}` rather than estimating from a hand-maintained price table. Haiku itself is deliberately excluded from the comparison — it's the known-passing baseline, not a useful column when the tool's purpose is finding a cheaper alternative that also clears the bar.
  - Final candidate list: `google/gemini-3.7-flash`, `z-ai/glm-5.3-flash`, `google/gemini-2.5-flash-lite`, `deepseek/deepseek-v4-flash`. Two originally-planned free-tier models (`z-ai/glm-5.2:free`, `google/gemma-4-31b-it:free`) were dropped after Gemma hit a real upstream 429 on the very first smoke-test call — free tier deemed too unreliable to include.
- **`prototypes/scripts/server_model_comparison.py`** (new) — thin Flask wrapper (port 5051), `/api/seeded-queries` and `/api/run`, following the existing `server.py` HTTP-wrapper convention.
- **`prototypes/web/index_model_comparison.html`** (new) — single-page UI: free-text query box (no ground truth), buttons for all 25 seeded queries + "run all", results table per model with pass/fail badge (auto-diffed against expected), cost/query, elapsed time, and full raw error text.
- **`prototypes/requirements.txt`** — added `httpx` (not previously listed, needed for the OpenRouter REST calls).
- **Root `venv/` recreated** — was silently broken: `pyvenv.cfg`/`activate` still hardcoded the pre-rename path (`.../nature-walker/venv`), so `source venv/bin/activate` set `VIRTUAL_ENV` to a nonexistent directory and `which python3` fell back to system Python (`/usr/local/bin/python3`), meaning nothing installed via `pip install` after activating actually landed in the venv. Confirmed unrelated to production (`app/backend/` has its own separate venv; root venv is dev-only tooling for `prototypes/`, referenced only in `prototypes/README.md`'s setup instructions). Recreated via `rm -rf venv && python3 -m venv venv`; a first `pip install -r prototypes/requirements.txt` was killed mid-run (slow dependency resolution, likely `claude-agent-sdk`) since it isn't needed for this prototype — user reinstalled the actually-needed packages manually in a separate terminal without `-q` (wants to see install output going forward).
- **Timeout bug found and fixed** in `model_comparison_spike.py`: `httpx`'s `timeout` parameter bounds the gap *between* reads, not total wall-clock response time. A live reproduction of "I want to see European robins" against `google/gemini-2.5-flash-lite` took 183.8s despite `REQUEST_TIMEOUT = 60.0`, because the response was apparently trickling data (keep-alives) that kept resetting the per-read timer. Fixed by wrapping the `httpx.post` call in a `ThreadPoolExecutor` and enforcing a real `WALL_CLOCK_TIMEOUT = 30.0` via `future.result(timeout=...)` — a stalling call now fails fast and cleanly instead of blocking the whole sequential run. Confirmed fixed: a re-run of the same query completed in 22.5s under the new ceiling (though it then returned a *wrong* answer — `family: Erithacidae` instead of `genus: Erithacus` — showing this model is both occasionally slow-to-stall and occasionally fast-but-wrong on this specific query).

Not a bug in the code under test: `anthropic_client.py`'s `TAXON_GUIDANCE` explicitly documents that GBIF's backbone taxonomy has no single "Reptilia" class, so Testudines (and the other reptile groups) are deliberately queried at `class` rank in this app, even though that's not standard biological taxonomy. The test's own name is just stale/wrong. Not fixed this session (out of scope for the prototype).
- **Live comparison results (one run against the 25 seeded queries, not exhaustive/repeated)**:

## Decisions and trade-offs

- **Decision:** Scope this session's prototype to taxon resolution only, not narration. **Why:** explicit user call — taxon resolution is "the main step to pass," and it has the harder bar (forced tool-use, exact-match ground truth) versus narration's fuzzier LLM-judged text, which also isn't built for model variability yet (still hardcoded to Anthropic's client shape).
- **Decision:** New-model calls go through plain `httpx` against OpenRouter's REST endpoint, not the `openai` SDK. **Why:** explicit user pushback on using an OpenAI-branded SDK to call non-OpenAI models "feels overcomplicated" — clarified that the SDK is just a convenience for OpenAI-shaped JSON, not a requirement, and `services/tts.py` already established the plain-`httpx` pattern for OpenRouter in this codebase.
- **Decision:** Haiku stays on its native Anthropic SDK path in the harness design (even though it was later dropped from the comparison entirely) rather than being routed through OpenRouter too. **Why:** the point of comparison is against Haiku's *real* production call shape, not OpenRouter's proxying of it.
- **Decision:** All calls run at each provider's default/unset temperature, not pinned to 0. **Why:** prod's real `resolve_taxon_filters` never sets temperature either (Anthropic default is 1.0) — pinning candidates to 0 would be comparing them under different conditions than what prod Haiku actually does.
- **Decision:** Sequential execution, no parallelism across models or queries. **Why:** matches the existing evals' execution style; avoids tripping free-tier rate limits (though free-tier models were later dropped entirely, this was decided before that).
- **Decision:** Cost tracked via OpenRouter's own `usage.cost` (`usage: {include: true}`), not a hardcoded price-per-token table. **Why:** more accurate — real provider-billed amount rather than an estimate that could drift from actual pricing.
- **Decision:** Haiku excluded from the comparison output entirely (not just deprioritized). **Why:** explicit user call — "we know it passes, so comparison isn't very helpful for this specific, more precise case." The tool's purpose is finding a cheaper alternative that clears the bar, not re-confirming the known baseline.
- **Decision:** No light TDD / pure-function unit tests written for the prototype's parsing logic, despite `prototypes/README.md`'s stated convention of testing deterministic non-LLM logic. **Why:** explicit user override this session ("No light TDD required") — a `test_model_comparison_spike.py` was drafted and then deleted per instruction before any implementation was built against it.
- **Decision:** Root `venv/` recreated rather than left broken or patched in place. **Why:** confirmed via grep across CI/deploy configs that it's referenced only by `prototypes/README.md`'s local dev setup instructions, with no production dependency — safe, low-risk cleanup.

## What was explored / learnt

- **Grill-me pass before building** (per CLAUDE.md's workflow) resolved: throwaway-prototype scope (not production); TTS comparison across ElevenLabs + OpenAI TTS + Kokoro-82M via OpenRouter; plain Anthropic call not Agent SDK (matches the already-validated `species_narrative_cost_experiment2.py` pattern); narrative input tested both names+locations-only and (not yet run) +Wikipedia extract; one combined walk narrative, not per-species segments; CLI + minimal HTML player deliverable; measure full-generation latency first, only build real streaming if >5-10s; fixed sample species data (not live pipeline) so provider comparisons are apples-to-apples; UI-trigger-placement question explicitly deferred until after this comparison.
- **ElevenLabs API key was scoped/restricted** — initial calls to a specific voice ID (`G17SuINrv2H9FC6nvetn`, "Christopher") and to `/v1/voices` both failed. `/v1/voices` returned 401 `missing_permissions` (`voices_read` not granted on the key) — user fixed key permissions mid-session. Even after that, both `G17SuINrv2H9FC6nvetn` and a since-deprecated ID for "Rachel" (`21m00Tcm4TlvDq8ikWAM`, not present in the account's actual voice list at all) returned 402 `paid_plan_required` — ElevenLabs' `category: "professional"`/library voices need a paid plan for API access even with correct key scopes; `category: "premade"` voices (confirmed via a real `/v1/voices` call — 23 available) work on the free tier. Settled on `onwK4e9ZLuTAKqWW03F9` ("Daniel — Steady Broadcaster", premade).
- **OpenRouter Kokoro-82M defaults to raw PCM, not MP3** — first successful call returned `Content-Type: audio/pcm;rate=24000;channels=1` with no request-side signal this would happen (not documented on the model's page). The saved `.mp3` file was actually headerless PCM — `file` reported it as generic "data", and the browser `<audio>` tag silently failed to play it (looked like a broken player, not a format bug, until headers were inspected directly). Fix: pass `"response_format": "mp3"` in the request body — confirmed via a standalone `requests.post` call that this flips `Content-Type` to real `audio/mpeg`. As a stopgap before the script fix landed, the already-generated raw-PCM file was made listenable by wrapping it in a WAV header (`wave` stdlib module, 24kHz/mono/16-bit) and repointing the existing HTML player at the `.wav` — this hand-edit was superseded once the script itself was fixed to request `response_format: mp3` and rerun.
- **Clearest finding of this prototype: Kokoro-82M via OpenRouter is currently the most promising TTS path** — meaningfully faster than ElevenLabs for this text length (ElevenLabs ≈10-11s TTS generation for ~900-950 chars; Kokoro ≈2-5s for similarly-sized text once returning real MP3 — roughly 2-5x faster), and priced cheaply per-character ($0.62/million chars via OpenRouter) with no obvious quality drop for this use case across the two voices listened to (`af_alloy`, `bm_george`) — fast, cheap inference with acceptable narration quality is a rare combination. Not yet validated with a structured side-by-side listening pass or a full cost-per-character table against ElevenLabs/OpenAI (see Next steps), so this is a strong early signal, not a final call — but it's the one to beat as OpenAI TTS gets added to the comparison.
- **Narrative length tuning**: first draft (200-300 word target) produced ~1900 chars ≈ 2 minutes spoken — too long. Converted to a target range using the observed ~950 chars/minute (~175 wpm) pace: **120-160 words / ~700-950 characters for a 45-60s narration**. Reran with `NARRATIVE_MAX_TOKENS` dropped from 600→300 and the word-count instruction updated; landed consistently in the 850-950 char range across reruns. Also removed a markdown title/heading (`# A Madrid Park Adventure`) the LLM was adding unprompted — explicit prompt instruction added ("do not include a title or heading — start straight into the narration") fixed it.
- **Prompt no longer names the location directly** — original draft hardcoded "Retiro Park, Madrid" in the prompt; changed to give the LLM only each species' name + raw GPS coordinates and explicitly ask it to infer location. Confirmed live: the model correctly inferred "Madrid," "Iberian Peninsula," and described the African/Australian/European species mix without being told any of it.
- **`venv/bin/python` had to be called directly** — `source venv/bin/activate && python ...` failed with `python not found` in this session's shell (PATH didn't pick up the venv's `python` symlink after activation, despite `python`/`python3`/`python3.13` all existing in `venv/bin/`); calling `venv/bin/python` explicitly worked reliably throughout.

## Decisions and trade-offs

- **Decision:** Session mode is throwaway prototyping (new scripts under `prototypes/`, no TDD), not a production increment. **Why:** matches this repo's established validate-cheaply-first pattern for every prior pipeline piece (waypoints, clustering, narrative, query validation). **Trade-off:** none — explicit user choice, first grill-me question.
- **Decision:** TTS comparison covers ElevenLabs, OpenAI TTS (not yet run), and Kokoro-82M via OpenRouter — not a self-hosted Kokoro deployment. **Why:** user wants a "send text, get audio back" reliable-endpoint experience; OpenRouter serves Kokoro behind exactly that shape with no inference-hosting infra to build, and its OpenAI-compatible API also gives a running start on the separately-backlogged "scope OpenRouter for broader model flexibility" item.
- **Decision:** Narrative generation uses a plain `messages.create()` call, not the Claude Agent SDK. **Why:** this repo already ran and recorded this exact experiment (`species_narrative_cost_experiment2.py` vs `experiment1.py`/`species_narrative_spike.py`) and found the Agent SDK's subprocess/agent-loop overhead unnecessarily slower/costlier for a single-shot, no-tool-loop task.
- **Decision:** One combined ~120-160 word narrative for the whole walk, not per-species segments. **Why:** explicit user call — simpler prototype, matches the "after the walk loads, one extra step" trigger hypothesis, and the original `species_narrative_spike.py` already validated this length/shape reads well as continuous prose.
- **Decision:** Fixed sample species data (hardcoded Retiro walk), not a live query-pipeline call, feeding the narrative prompt. **Why:** isolates the narrative/TTS variables under test from GBIF/LLM query variability, so provider/voice comparisons are apples-to-apples across reruns. User flagged this will need to expand into multiple fixed sample walks for broader evaluation (see Next steps).
- **Decision:** Generated `.mp3`/`.wav` files are gitignored; the HTML player pages are not (kept trackable, consistent with this repo's existing committed-prototype-HTML-artifacts convention). **Why:** explicit user request — audio binaries shouldn't enter git history.
- **Decision:** UI-trigger-placement question (where the "narrate this walk" icon/button lives) explicitly deferred until after this narrative/TTS comparison has real latency and quality data to design against, rather than sketched in parallel. **Why:** explicit user choice during the grill-me pass — avoids designing a trigger around numbers that don't exist yet (e.g. whether streaming playback controls are even needed).

## Session 2 — Species info + narrative guide prototype (Claude Agent SDK)

### What was built

- `prototypes/species_narrative_spike.py` — new prototype script. Pipeline: GBIF common-name lookup (`gbif_common_name`) → per-species description generated by an isolated Claude Agent SDK agent with a single custom tool (`fetch_wikipedia_summary`, wrapping the Wikipedia REST summary API, registered via an in-process `create_sdk_mcp_server`) → a second isolated Agent SDK call (no tools) that combines all 5 descriptions + coordinates into one David Attenborough-style narrative → an enriched Leaflet map with per-species popup cards (name, image, description) and a narrative side panel.
- `prototypes/retiro_narrative_map_with_info.html` — output of the above (5 species: Black-billed Magpie, Iberian Green Woodpecker, Egyptian Goose, Black Swan, Common Mallard — all in Retiro Park). Original `prototypes/retiro_narrative_map.html` from an earlier run in this session was deliberately kept, not overwritten, per instruction — the script now writes to the `_with_info` filename specifically to avoid future collisions with other prototype map outputs.
- `prototypes/requirements.txt` — added `claude-agent-sdk` and `python-dotenv` (removed an initial, incorrect `anthropic` entry — see below).
- `.env` (repo root, gitignored, user-created) — holds `ANTHROPIC_API_KEY` for the script; loaded via `load_dotenv()` at the top of `species_narrative_spike.py`. Deliberately not exported into the interactive shell — Claude Code sessions must not use API-key billing for interactive work (see below).
- Detailed per-agent-call logging added: full prompt text, tool calls, agent text, and the raw SDK `usage` dict (including `cache_creation_input_tokens` / `cache_read_input_tokens` / `num_turns` / `duration_api_ms`) is printed for every call, plus a widened summary table at the end (`extract_usage_stats()` helper).

### What was explored / learnt

- **`/claude-api` skill dumped ~309k tokens into context** on first invocation because no project language could be auto-detected (no `.py`/`.ts` source files existed yet at that point) — it fell back to including *every* language's full reference doc instead of asking which one to load. Root-caused and explained to the user; avoided on subsequent lookups by fetching only the specific Agent SDK docs pages needed via `WebFetch`.
- **Initial implementation used the wrong SDK.** First draft used the Anthropic API's Tool Runner (`client.beta.messages.tool_runner`, package `anthropic`) — this is explicitly *not* the Claude Agent SDK (the `claude-api` skill's own docs state it "does not generate Claude Agent SDK code"). Corrected after explicit user correction, referencing `https://code.claude.com/docs/en/agent-sdk/overview`. Rebuilt using the real `claude_agent_sdk` package (`query()`, `ClaudeAgentOptions`, `@tool` decorator, `create_sdk_mcp_server()`), verified field names (`ResultMessage.usage`, `.total_cost_usd`, `.duration_ms`, `.num_turns`, etc.) against the actual `claude-agent-sdk-python` GitHub source rather than trusting a `WebFetch`-summarized paraphrase, which contained inaccurate field names (`total_input_tokens`/`total_output_tokens` don't exist — the real field is `usage: dict[str, Any]`).
- **The Python Agent SDK spawns the `claude` CLI as a subprocess** (unlike the TypeScript SDK, which bundles a native binary) — confirmed the CLI (`v2.1.214`) was already on `PATH` locally, so no extra install was needed.
- **Agent SDK apps cannot bill via a claude.ai subscription.** Per the SDK's own docs: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products... Please use the API key authentication methods described in this document instead." Confirmed this Claude Code *interactive* session itself was authenticated via Claude Pro subscription login (`/status` → `Login method: Claude Pro account`), not an API key — the prototype script's `.env`-scoped key is separate and does not affect the interactive session's billing.
- **Dead end:** spent significant time investigating a recurring `⚠ claude.ai connectors are disabled because ANTHROPIC_API_KEY or another auth source is set` warning shown by Claude Code. Checked: shell env (`env | grep -i anthropic`, `ANTHROPIC_AUTH_TOKEN`), shell profile files (`.zshrc`, `.zprofile`, `.bashrc`, `.bash_profile`, `.profile`), `direnv` (not installed), `~/.claude/settings.json`, `~/.claude.json` — all clean, no API key or auth token found anywhere. Root cause not identified; `/status` confirms the session is in fact on the Pro subscription regardless, so concluded the warning is likely stale/transient and not currently blocking anything. Not resolved — flagged as a minor open item, not a blocker.
- **Cost driver identified via the raw `usage` dict:** `input_tokens` alone is misleading (~4 tokens per call) because Claude Code's own system-prompt/tool overhead is prompt-cached. The real cost driver is `cache_creation_input_tokens` (~2,000 tokens on *every* call, ~12,181 tokens total across the run) — each per-species `query()` call is a fully isolated agent session with no cross-call cache reuse, so each one re-pays the ~2,000-token cache-write premium. `cache_read_input_tokens` (~1,800) on the 5 description calls suggests a smaller shared base is being reused across those calls, but the narrative call (a separate session) reads 0 cache. `total_cost_usd` from the SDK already prices this correctly; it was the per-step display that initially hid it.
- **GBIF data was live-fetched in the first draft** by importing `fetch_gbif`/`select_species`/`order_waypoints` from `waypoint_spike.py` — removed per explicit instruction (unnecessary latency + cross-dependency on another prototype script). Captured the actual current GBIF result once (Retiro Park, 2026 occurrences, top 5 by count) and hardcoded it as `HARDCODED_SPECIES` in `species_narrative_spike.py`, including each species' GBIF `species_key` (previously derived by searching raw occurrence records, no longer needed).

### Decisions and trade-offs

- **Decision:** Use the Claude Agent SDK (not the plain Anthropic API / Tool Runner) for both the per-species description step and the narrative step. **Why:** explicit user requirement — wanted to test the SDK's agent/tool-calling building blocks (in-process MCP server via `create_sdk_mcp_server`) even in an otherwise deterministic pipeline, as a step toward exploring these components for future orchestration. **Trade-off:** heavier dependency (spawns a `claude` CLI subprocess per call) and, as discovered above, no cross-call prompt-cache reuse — meaningfully higher cost per call than a single conversational API session would have.
- **Decision:** One fully isolated agent call per species (single `fetch_wikipedia_summary` tool), plus one separate isolated call (no tools) for the combined narrative. **Why:** matches the isolation design agreed in the earlier `/grill-me` session for this feature. **Trade-off:** this isolation is the direct cause of the cache-write cost overhead above — a single long-lived session across all species would likely be cheaper, at the cost of losing per-species isolation.
- **Decision:** Sonnet 5 for both steps; `effort="medium"` for descriptions, and narrative dropped from `effort="high"` to `effort="medium"` at user's request. **Why:** cost baseline, to be compared against Opus 4.8 later per the original evaluation plan (cost, time, accuracy).
- **Decision:** Hardcode the captured GBIF species data rather than calling GBIF live at runtime. **Why:** explicit instruction to avoid the added latency and the cross-dependency on `waypoint_spike.py`. **Trade-off:** data is now a point-in-time snapshot; needs manual re-capture (re-run the snippet against `waypoint_spike.py`'s functions) if fresher GBIF data is wanted.
- **Decision:** Full prompt/response/raw-usage logging for every agent call (`extract_usage_stats()`, printed prompts, tool calls, agent text). **Why:** explicit visibility requirement so cost/time/accuracy can actually be evaluated from the logs, not just inferred from a summary table.
- **Decision:** No tests written for this prototype. **Why:** explicit user instruction, consistent with the rest of `prototypes/` (throwaway scripts, no test suite), overriding the default TDD workflow in `CLAUDE.md`.

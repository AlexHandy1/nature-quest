## What was explored / learnt

- **Prototype reference material was not promoted wholesale.** Initial plan was to copy `prototypes/reference/`'s 3 curated JSON key-caches (kingdom/class/order) and the 220-line `gbif_docs_summary.md` straight into production, matching the spec's §6 implementation mechanics. On review: the class/order caches encode multi-key concepts (reptiles = 4 classes, fish = 5 orders) that Slice 2's single-`taxonFilter` schema can't represent anyway (mixed-taxa is explicitly out of scope), so promoting them would be dead data. Decided instead on live-only resolution (no cache) — see Decisions.
- **Model choice was corrected mid-session.** Initially assumed `claude-sonnet-5` per REQ-006's stated "explicit prior decision." User corrected this against `prototypes/README.md`: later prototype work (`e2e_walk_spike.py`, `server.py`) found Haiku matches Sonnet's quality on this call shape for ~half the cost, and switched the pipeline default accordingly. REQ-006 in the committed spec was stale and has been corrected in-document.
- **Density-cluster hotspots deliberately deferred, not dropped.** `e2e_walk_spike_clustering.py`'s `cluster_species_hotspot()` (adaptive N×N density grid) is the validated, more-correct approach for hotspot placement, but REQ-011 explicitly scopes this slice to a plain centroid since there's no waypoint/route yet to place it for. This is already tracked as a PRD success criterion (Slice 4: "Species hotspots use density-cluster centroids, not naive averages"), so nothing new was added to the backlog — code comments and the spec's REQ-011 wording now point explicitly to Slice 4 and the source file.
- **Local-dev vs. production secret handling is a genuine two-path design, not a single "clean" abstraction.** Initially proposed a single `build_client()` with no branching; user correctly pushed back that local smoke-testing needs remain even after REQ-005 ships. Landed on: `K_SERVICE` (Cloud-Run-injected, zero config) selects Secret Manager vs. local `.env`/env var. Noted as tech debt: relying on a platform-specific var rather than an explicit `ENVIRONMENT` config flag we control — acceptable for now, worth redressing later.
- **Cross-test state pollution** was a recurring gotcha: both `slowapi`'s in-memory limiter and `query_budget`'s module-level counter are process-global, shared across the entire pytest session (since `TestClient(app)` and the `app` singleton are imported once). Fixed via `tests/conftest.py` autouse fixtures (`app.state.limiter.reset()`, `query_budget.reset()`) run before every test.
- **`slowapi` requires a `Request` parameter** on the decorated route function for its `@limiter.limit(...)` decorator to work — route signature is `submit_query(request: Request, body: QueryRequest)`, not just `body: QueryRequest`.

## Decisions and trade-offs

- **Decision:** Taxon-key resolution is live-only (`species/match` on every resolved query), no curated cache files promoted from `prototypes/reference/`. **Why:** the class/order caches encode multi-key categories (reptiles, fish) unusable under this slice's single-filter schema; live resolution also means every resolved query genuinely exercises the guardrail work (retry/timeout/scale-guard) rather than skipping it on cache hits — arguably closer to this slice's stated purpose of proving guardrails against a real third-party call. **Trade-off:** one extra ~100-300ms round trip per resolved query, accepted given low/pre-launch traffic. Deviates from the committed spec's REQ-008 (cache-first design); spec updated accordingly.
- **Decision:** LLM model is `claude-haiku-4-5-20251001`, not `claude-sonnet-5`. **Why:** corrected per `prototypes/README.md`'s later, validated finding (Haiku matches Sonnet quality here for ~half cost). REQ-006 in the spec was stale and has been corrected in-document, with the correction's rationale recorded inline.
- **Decision:** System prompt for taxon resolution (`TAXON_GUIDANCE`) is ~15 lines, not the prototype's 220-line `gbif_docs_summary.md`. **Why:** most of that doc covers `q`/`sort`/multi-filter behavior this slice's schema doesn't have; the schema's own `taxonRank` enum already structurally prevents the unranked-clade problem the doc spent a section explaining in prose.
- **Decision:** `hotspot_lat`/`hotspot_lon` use a plain centroid, not `cluster_species_hotspot()`'s density-grid approach, this slice. **Why:** REQ-011 explicitly scopes this out — no waypoint/route exists yet to place a hotspot for. **Trade-off:** already tracked as PRD Slice 4's job; spec wording and code comments now point there explicitly by name.
- **Decision:** `build_client()` branches on `K_SERVICE` presence — Secret Manager fetch when set (Cloud Run), local `.env`/env var otherwise, with the Secret Manager branch currently raising `NotImplementedError` (REQ-005 not yet built). **Why:** local dev/smoke-testing needs (fast, no GCP auth dependency) are genuinely different from production's log-dump risk (REQ-005's actual concern is `JsonLogFormatter` accidentally sweeping `os.environ`, a deployed-container-specific risk). Failing loudly rather than silently falling back to an env var in production was a deliberate choice. **Trade-off:** relies on a Cloud-Run-injected platform variable (`K_SERVICE`) rather than an explicit config flag — noted as tech debt to possibly revisit.
- **Decision:** All guardrail threshold values deferred by `CON-002` (max query length, per-IP rate limit, daily LLM-call cap, GBIF scale-guard threshold, GBIF retry count/timeout) were chosen this session via explicit user confirmation. **Why:** user-confirmed via choice prompts during the build, informed by the prototype's own already-validated values where applicable (scale guard, retry/timeout). Per this project's disclosure convention (`CON-002`/`ADR-007`/`ADR-008`), the exact values are deliberately not restated in this document either — they're build-time constants in the source (`app/backend/models/query.py`, `services/rate_limiter.py`, `services/query_budget.py`, `services/gbif_client.py`), consistent with the same convention already applied to the spec itself.
- **Decision:** A real-API smoke test (`@pytest.mark.eval`, `tests/test_smoke_llm.py`) was built as a precursor to REQ-024's fuller DeepEval suite, not a replacement for it. **Why:** user wanted confirmation the real integration actually works before adding DeepEval's added sophistication. Both birds→`class/Aves` and plants→`kingdom/Plantae` pass against the live API.
- **Decision:** `pytest.ini`'s `addopts = -m "not eval"` excludes eval tests from the *default* `pytest` run, not just CI. **Why:** matches REQ-024's literal spec text ("excluded from the default pytest run and from CI's... gate") — an earlier version only excluded via CI's explicit `-m` flag, which a local `pytest` run would have missed, silently incurring real API cost.

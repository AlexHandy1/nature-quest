# Work Summary — 18 August 2026

## What was built

- **`prototypes/scripts/narration_wikipedia_spike.py`** (new) — throwaway prototype: fetches a Wikipedia extract per species (mirrors `app/backend/services/wikipedia_client.py`'s common-name-first/scientific-name-fallback/disambiguation-check resolution logic, but keeps `extract`/article `url`, which production's `_fetch_summary` discards after using only the image) and generates two variants of the same 5-species Retiro Park walk narrative side by side: baseline (names + locations only, matches `narration_tts_spike.py`) vs. Wikipedia-grounded. Writes an HTML comparison page (`prototypes/artifacts/narration_wikipedia_spike.html`) with both narratives, timing/token/cost stats, and a list of the Wikipedia sources used. Text-generation only, no TTS — deliberate, to isolate the grounding question's own cost/latency from the already-validated narrative→audio round trip.
- **`prototypes/scripts/narration_eval_spike.py`** (new, forked from the above per this folder's copy-not-edit checkpoint convention) — consolidates generation + an automatable eval pass into one script, run against both narrative variants so the report shows whether the checks actually distinguish narration quality rather than always passing. Five agreed criteria, ending state:
  - Programmatic (regex, no LLM call): `length` (≤1000 chars — generation targets 120-130 words as the primary control, this is a hard backstop), `no_time_refs` (no time-of-day/season/"today" statements), `no_dash_pauses` (no "—"/" - " artificial pauses, unreliable for TTS — **not** left to the LLM: `sanitize_dash_pauses()` deterministically swaps dashes for a comma right after generation, before eval or rendering; the check is now a regression guard on the sanitizer itself).
  - LLM judge (Sonnet 5 by default — a different model class than the Haiku narrator; `--judge-model` flag can swap to Haiku), one combined structured-output call per narrative: `faithfulness` (species facts only from the retrieved extracts) and `no_habitat_claims` (no specific habitat/environment claim ungrounded in an extract). Both get a **minor/major severity split** per finding — only "major" (fabricated, or a broad whole-walk claim) fails the check; "minor" (defensible paraphrase, or a real per-species fact just attached to the wrong sentence) is still surfaced in the report but doesn't fail it. Judge output includes a free-text `reasoning` field, printed to console and shown in the HTML report, for human sanity-checking.
  - A sixth criterion (jargon/non-expert readability) was built two ways this session — a curated wordlist, then an LLM judge — and dropped entirely: the wordlist doesn't generalise past the 5 species tested, and the LLM-judge version proved unreliable even with a substring-presence backstop (see below).
- Fixed two real bugs found live during this build:
  - **HTML-injection bug**: the Sonnet 5 judge leaked stray `</reasoning>`/`</invoke>` tool-call artifacts into its free-text `reasoning` field on one run, which broke the report page's DOM when inserted raw. Fixed by `html.escape()`-ing all model-generated text (narrative, reasoning, check details) before embedding.
  - **Variable-shadowing bug**: `generate_report_page()`'s local page-content variable was named `html`, shadowing the module-level `html` import within that function's scope — caused `UnboundLocalError` on `html.escape(...)` calls earlier in the function body. Renamed the local to `page_html`.
- Iterated the `GROUNDED_FACTS_GUIDANCE` prompt through several rounds in response to eval findings: don't round a specific fact up into an absolute claim (a list of countries isn't "every continent"/"worldwide"); a habitat detail must stay tied to the one species whose extract supports it, phrased as true only for that species in that moment — not a blanket claim like "throughout these wetlands," since habitat can vary across a geographic area even where one species' extract mentions it; when stating where a species is/isn't found, name the actual place from the extract (e.g. "the Iberian peninsula") rather than a placeless absolute like "found nowhere else on Earth," which could be misread as this one walk's exact spot being the species' entire range.
- Added a `--judge-model` CLI flag (default `claude-sonnet-5`, alternative `claude-haiku-4-5-20251001`) to `narration_eval_spike.py`, threaded through `run_llm_judge`/`run_eval`/`main`/`generate_report_page`, so the judge model is visible in console output, cost tables, and the HTML report rather than hardcoded.
- **`prototypes/README.md` rewritten**, same philosophy as the 15 Aug `ARCHITECTURE.md` trim: removed the "What's proven vs. still open" section (status/decision content that goes stale against the actual prototypes and duplicates `docs/status_docs/`) and condensed each numbered script section from multi-paragraph run-by-run narration ("validated this round," "known bug fixed," per-metric detail) down to what was built and why, in 1-3 sentences. Added §11 covering this session's and 14 Aug's audio-narration track (`narration_tts_spike.py`, `narration_wikipedia_spike.py`, `narration_eval_spike.py`), which hadn't been documented there before. Caught and fixed one inaccuracy while drafting it: an early version claimed `narration_eval_spike.py` imports from `narration_wikipedia_spike.py` (stated as a second deliberate cross-import exception alongside `server.py`) — checked the actual file and it doesn't; it's a standalone duplicate, per the normal convention, corrected before finalizing.

## What was explored / learnt

- **Production's Wikipedia integration doesn't currently fetch description text at all.** `wikipedia_client.py`'s `_fetch_summary()` already retrieves the full summary JSON (including `extract`) for its image lookup, but discards everything except the image. There is no existing "description" data path elsewhere in production. Confirmed before building anything, per explicit user direction to draw on the existing access pattern rather than invent a divergent one — promoting this later is a one-line change to an already-existing function, not a new integration to reconcile.
- **The Wikipedia REST summary endpoint (`/page/summary/{title}`) returns a short, curated lead-paragraph extract, not the article** — this is why extracts were consistently ~350-500 characters this session. Longer material is available but wasn't used this session (logged here to revisit, not acted on):
  - `action=query&prop=extracts&exintro&explaintext` (classic MediaWiki API) — full lead section (2-5 paragraphs), a natural middle ground.
  - Same without `exintro` — the entire article, all sections, plain text — could easily 10x prompt tokens per species and pull in content irrelevant to a 120-130 word narration (population/conservation stats, full taxonomy tables).
  - `exsentences=N` — tunable cap on the lead section.
  - REST `/page/html/{title}` — full article as structured HTML, would need section parsing to isolate e.g. just "Description".
  - Wikidata (separate API, keyed by the article's QID) — structured facts (conservation status, taxonomic rank), not prose.
- **The LLM judge can hallucinate findings sourced from the extracts rather than the narrative it's meant to be grading.** First jargon-check run cited "Anatidae," "endemic," "sibilant hiss-like call" as narrative jargon when none of those terms literally appeared in the graded narrative — they were lifted from the reference extracts instead. Fixed for the criteria that were kept (faithfulness, habitat) via an explicit prompt instruction ("every claim you report must be wording that actually appears in the NARRATIVE, never a term that only appears in the extracts"); a substring-presence backstop filter was also built for the jargon check specifically but removed along with the whole criterion once it was dropped.
- **"Found nowhere else on Earth" is a technically accurate paraphrase of "endemic to X," but creates a real geographic-scope risk distinct from true overgeneralization.** A listener standing at one walk location could misread a placeless exclusivity claim as "this exact spot is the species' only home," even though the underlying fact (endemic = occurs nowhere else) is correct. This is a different failure mode from the mallard case ("breeds across the Americas, Eurasia, North Africa, +10 introduced countries" → "every continent"), which is a genuine expansion of the stated range. Both needed separate prompt/judge handling.
- **Haiku as the eval judge (`--judge-model claude-haiku-4-5-20251001`) is meaningfully cheaper — roughly 2-2.5x — and produced comparable-quality findings/reasoning across the runs tested this session** ($0.007-0.008 for 2 judge calls vs. $0.018-0.021 with Sonnet 5; total harness run ~$0.011 vs. ~$0.022). Not exhaustively validated — only a handful of runs — but a promising signal that Haiku could serve as the default judge for routine runs, reserving Sonnet 5 for periodic/higher-stakes spot checks.
- **Run-to-run variance is real and material with only one sample per variant.** Baseline scored anywhere from 1/5 to 4/5 across runs this session as its (non-deterministic) generation happened to fabricate more or fewer details; grounded ranged from 3/5 to 5/5 for the same reason plus prompt-guidance iteration. The harness correctly distinguishes quality within a run, but a single run's pass count isn't a stable signal — would need N samples per variant averaged to use this as a gate on anything.
- **Eval judging is the dominant cost in this harness, not narrative generation.** Roughly 5-6x the generation cost with Sonnet 5 as judge, ~2x with Haiku as judge — worth keeping in mind when scoping a production eval harness's per-run cost.

## Decisions and trade-offs

- **Decision:** Wikipedia extract fetching in the prototype mirrors (duplicated, not imported) production `wikipedia_client.py`'s exact resolution order and disambiguation check, extended to also keep `extract`/`url`. **Why:** explicit user direction — the prototype should draw on the existing production access pattern, not invent a separate one that would need reconciling later.
- **Decision:** Dash-pauses are fixed by deterministic post-processing (`sanitize_dash_pauses()`, regex swap to comma), not left to LLM prompt compliance. **Why:** the LLM was inconsistent at avoiding em-dashes even when explicitly instructed; this is a mechanical TTS-readability fix, not a judgment call, so it doesn't need to be probabilistic.
- **Decision:** Faithfulness and habitat-claim judge findings each get a minor/major severity split; only "major" fails the check. **Why:** explicit user feedback — the judge was failing narratives for defensible stylistic paraphrase and reasonable minor extensions, not real inaccuracy. Minor findings stay visible in the report (not silently dropped) so a human can still review the trail.
- **Decision:** Jargon check dropped entirely (tried as both a wordlist and an LLM judge). **Why:** explicit user call — a wordlist only ever covers species already tested and won't generalise; the LLM-judge version proved unreliable (hallucinated findings sourced from extracts, not narrative) and wasn't providing actionable signal even with a backstop filter.
- **Decision:** `narration_eval_spike.py` is a fork of `narration_wikipedia_spike.py`, not an in-place edit. **Why:** this folder's established copy-not-edit checkpoint convention (see `prototypes/README.md`) — `narration_wikipedia_spike.py` stays a stable, already-validated reference for the narrower "just the narrative, no eval" question.
- **Decision:** Eval judge defaults to a different model class (Sonnet 5) than the Haiku narrator, with Haiku available as an explicit `--judge-model` flag rather than a silent swap. **Why:** wanted confidence the judge isn't "grading its own homework" by default, while keeping cost comparison easy and visible given judging is the dominant cost driver.
- **Decision:** TTS intentionally excluded from both prototypes built this session. **Why:** explicit user call — assessing the text-generation/grounding step's own cost and latency first; adding audio would add cost/complexity noise to a comparison specifically about the grounding step. `narration_tts_spike.py` (14 Aug) already validated the narrative→audio round trip separately and is untouched.
